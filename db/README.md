# Arifaa Platform — database design (v1 baseline 4 Nov 2026, migrations since)

One RDS PostgreSQL server per company, five databases, one login per application.

| File | Database | Owner login |
|---|---|---|
| `ddl/00_roles.sql` | (server) | creates `cms_app`, `crm_app`, `automation_app`, `agents_app`, `reporting_ro` |
| `ddl/01_crm.sql` | `crm` | `crm_app` — 45 tables, quote-freeze triggers, `consume_send_grant()`, append-only audit, default settings |
| `ddl/02_automation.sql` | `automation` | `automation_app` — 12 tables; since 11 Nov also the job schedule table (`scheduled_jobs`) and the opt-out log |
| `ddl/03_agents.sql` | `agents` | `agents_app` — 14 tables (+ LangGraph checkpoint/store), pgvector HNSW (`vector(1024)`, Qwen3-Embedding-0.6B) |
| (Payload) | `cms` | `cms_app` — tables generated by Payload collections |
| (Phoenix) | `phoenix` | AI-trace store of the self-hosted Arize Phoenix (created by infra, not by these files) |
| `tests/test_rules.sql` | crm, automation, agents | 21 business-rule tests |

**The DDL files are the 0001 baseline and are never edited.** Every change since is an Alembic revision in
`apps/arifaa-pack/src/arifaa_pack/migrations/<db>/versions/` (`crm_0002`…, `automation_0002`…, `agents_0002`…),
applied by `kx migrate` (idempotent; tests build their databases the same way).

## Run locally

```bash
make up            # pgvector Postgres 18 + Redis (docker compose)
make migrate       # 0001 baseline from these files, then every later revision
```

Or by hand on PostgreSQL 16+ with pgvector (baseline only):

```bash
for d in crm automation agents; do createdb $d; done
psql -f ddl/00_roles.sql
psql -d crm        -v ON_ERROR_STOP=1 -f ddl/01_crm.sql
psql -d automation -v ON_ERROR_STOP=1 -f ddl/02_automation.sql
psql -d agents     -v ON_ERROR_STOP=1 -f ddl/03_agents.sql
psql -d crm        -f tests/test_rules.sql | grep -E 'PASS|FAIL'   # expect 21 PASS
```

No cross-database foreign keys: references across databases are plain `uuid` columns named `*_ref`.
The background-job queue is no longer a library schema (Procrastinate was replaced by Celery on 11 Nov): due
work and long timers are rows in `automation.scheduled_jobs`, swept by Celery Beat every 30 seconds.
