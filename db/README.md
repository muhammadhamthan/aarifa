# Arifaa Platform — database design (v1, 4 Nov 2026)

One RDS PostgreSQL server per company, four databases, one login per application.

| File | Database | Owner login |
|---|---|---|
| `ddl/00_roles.sql` | (server) | creates `cms_app`, `crm_app`, `automation_app`, `agents_app`, `reporting_ro` |
| `ddl/01_crm.sql` | `crm` | `crm_app` — 45 tables, quote-freeze triggers, `consume_send_grant()`, append-only audit, default settings |
| `ddl/02_automation.sql` | `automation` | `automation_app` — 12 tables (+ procrastinate's own) |
| `ddl/03_agents.sql` | `agents` | `agents_app` — 14 tables (+ LangGraph checkpoint/store), pgvector HNSW |
| (Payload) | `cms` | `cms_app` — tables generated by Payload collections |
| `tests/test_rules.sql` | crm, automation, agents | 21 business-rule tests |

## Run locally

```bash
# PostgreSQL 16+ with pgvector
for d in crm automation agents; do createdb $d; done
psql -f ddl/00_roles.sql
psql -d crm        -v ON_ERROR_STOP=1 -f ddl/01_crm.sql
psql -d automation -v ON_ERROR_STOP=1 -f ddl/02_automation.sql
psql -d agents     -v ON_ERROR_STOP=1 -f ddl/03_agents.sql
psql -d crm        -f tests/test_rules.sql | grep -E 'PASS|FAIL'   # expect 21 PASS
```

These files are the source for the first Alembic migration of each database in the code step.
No cross-database foreign keys: references across databases are plain `uuid` columns named `*_ref`.
